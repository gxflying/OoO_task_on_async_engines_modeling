ATTENTION PIPE / MODELING V3

动态 full / empty barrier ID 容量

每条数据依赖独占一个 full ID；消费者真正开始时 WAIT 并回收。buffer 等全部消费者完成后，get_and_set 新的 empty ID；下次写入开始时回收 empty。

同一个 ID 是 one-hot：1 << slot。多输入 WAIT 使用多个 one-hot 位的 OR。动态 ID 在操作完成时才分配；队列先携带逻辑依赖边，运行时绑定 slot + generation。

容量与性能对照

总 ID 数同时计入 full 和 empty，全部动态复用。初始每个空闲 buffer 需要一个已 SET 的 empty；“初始化阻塞”和“死锁”不作为完成性能。

执行流水与 ID 生命周期

浅色方块：实际计算时间红色尾段：计算已结束，ID 不足导致无法完成虚线边框：越过队列旧指令发射

Buffer：从分配开始占用，直到实际释放

浅色：整个占用区间蓝线：生产者计算绿线：消费者读取灰色：外部源输入

v3 在指令实际发射时分配 buffer。蓝线、绿线只计 start→compute_end；计算结束后的发布阻塞、等待消费者等时间仍计入浅色占用区间。未释放的 buffer 显示到轨迹停止时刻，并以红色右边界标记。

点击 buffer 查看物理槽位、复用代数、占用时间及生产者/消费者计算时间。

协议与验证边界
    

  • 每轮 10 条依赖边，逐边独立 full。vector1R2 的两个消费者各有一个 full；不能合并成一个被首次 WAIT 清掉的位。
    • 

  • 动态 full/empty 共用同一 ID 池。初始 empty 也真实占用容量；完成后只剩每个空闲 buffer 对应的 ready empty，full 已全部回收。
    • 

  • 完成时一次性申请该操作所需的全部 full + empty，成功后才发布、释放 engine 和输入。计算结束时刻 compute_end 与成功完成时刻 end 分开记录。
    • 

  • 整批原子发布是本模型约定。若改为分步发布或预留 ID，死锁与容量阈值可能改变。
    • 

  • fan-out 的 empty 由最后一个直接消费者完成触发，仍需要引用计数 / join 元数据；一位 barrier 本身不承担多消费者计数。
    • 

  • 同一时刻不断重试 SET、WAIT、释放，直至无进展；WAIT 回收的 ID 可以立即解锁另一操作的完成。
    • 

  • 保留 v2 的池内 RDMA 输入与末级 fa2 立即被外部接收假设；不额外添加外部 full。指令时长、队列深度和前端顺序不变。
    • 

  • 不建模 ID 分配、信号传递、动态绑定的额外延迟和端口带宽。本次结论是容量与生命周期模型，不是完整 ISA 编码或真实硬件性能。
    • 

复现与有效配置


v1 / v2 保持不变。所有流水、mask、ID 生命周期、死锁状态均来自实际仿真。
